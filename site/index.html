sudoconsole

secure sudo wrapper for CLI agents

Install

The recommended way to install sudoconsole is the one-line installer below. It detects your platform (Linux/macOS × amd64/arm64), downloads the matching tarball from the latest GitHub release, verifies the cosign signature, and drops the binary in your PATH.

curl -fsSL https://LeandroLCD.github.io/sudoconsole/install.sh | sh

You can also pin to a specific release:

curl -fsSL https://LeandroLCD.github.io/sudoconsole/install.sh | \
  sh -s -- --version v0.3.0

Or pick a custom install location:

curl -fsSL https://LeandroLCD.github.io/sudoconsole/install.sh | \
  sh -s -- --to ~/.local/bin

Flags:

FlagMeaning
--version <tag>Pin to a release tag (default: latest).
--to <dir>Install to <dir> instead of detecting the default (/usr/local/bin or ~/.local/bin).
--no-verifySkip the cosign signature check (not recommended).
--no-modify-pathSuppress the PATH instructions on user-mode installs.
-h, --helpShow the full help.

Environment variables: SUDOCONSOLE_VERSION, SUDOCONSOLE_INSTALL_DIR, SUDOCONSOLE_NO_VERIFY=1, SUDOCONSOLE_NO_MODIFY_PATH=1.

What it does

sudoconsole lets any AI coding agent (Kilo, Claude Code, Gemini, Aider, Codex, Copilot, …) execute sudo commands without ever exposing the password in logs, history, agent event streams, or /proc/<pid>/{cmdline,environ}. It also enforces a security policy that blocks remote-access and credential-exposure commands by default.

Secret-safe

Password is fed via PTY stdin (never argv); the credential is heap-allocated and zeroized on use.

Audited

Every Block / Allow / Warn decision can be appended to a JSONL log.

Policy-first

blocklist / allowlist / audit modes; lint custom patterns with policy validate.

Single static binary

4 GOOS / GOARCH pairs shipped via goreleaser + Homebrew tap + .deb / .rpm.

Quickstart

# prime the sudo cache — prompts for the password on a TTY, never echoed
sudoconsole auth

# inspect cache status
sudoconsole check
sudoconsole --format json check

# run a privileged command under the policy
sudoconsole exec apt update

# blocked by default
sudoconsole exec ssh user@host      # exit 64

# override once, with audit + interactive confirm
sudoconsole exec --policy-override "debugging" --yes ssh user@host

# install adapters for every detected CLI agent
sudoconsole install

Why a separate install script?

Most users land on the GitHub repo, see a README with build instructions, and leave. Hosting the installer on GitHub Pages means:

  • The one-liner curl … | sh works before anyone clones the repo.
  • The script can be pinned to a specific release tag with --version.
  • Updates ship without touching the README — push a tag, the next install pulls the new binary.
